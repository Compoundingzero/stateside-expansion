# ELN submission service

`createSubmissionService({dbPath, setupToken, origin, secureCookies, retentionDays, getClientAddress})` is independent of environment variables and process user identity. The root HTTP server calls and awaits `handle(req, res)` before static routing, then calls `close()` during shutdown. API responses always use private/no-store and noindex headers. Storage must be a real persistent volume in production; the service does not decide whether a directory is a mounted volume.

The owner chooses the first password using a random setup token of at least 32 characters. The token travels in the URL fragment on the browser, is immediately removed there, and is posted in a JSON body. The database permits one owner only. Passwords use salted scrypt; sessions are random opaque cookies, stored only as SHA-256 hashes and expiring after 12 hours. Production cookies use the `__Host-` prefix, Secure, HttpOnly, Path=/ and SameSite=Strict. `secureCookies:false` is for local HTTP tests only.

All mutation requests require the configured exact Origin. Public bodies are bounded to 32 KiB. Interest records contain name, company, optional free-text ARR and email; enquiries contain comments and email. The website honeypot returns the same acknowledgement without storing the submission. No confirmation or marketing email is sent. No request bodies, passwords, email addresses or IP addresses are logged.

Public submission limits are 10 attempts per 15 minutes for each selected address, and 5 accepted attempts per hour for each case-folded email address. The single owner's login limit is 8 attempts per 15 minutes; setup is limited to 5 attempts per 15 minutes. Email and owner-account limits are independent of forwarding headers. All rate keys are HMAC hashes held only in bounded process memory and reset on restart.

The default address selector uses the socket peer and ignores forwarding headers. Root may explicitly supply `getClientAddress(req)` for the specific Railway public-HTTP-edge deployment, selecting a validated singular `X-Real-IP` only when that deployment's ingress assumptions hold. No TCP proxy or untrusted direct/private ingress may be treated as that public edge. The selected address is an abuse signal, never an authorization boundary. Invalid selected addresses fall back to the socket peer. Railway documents the header at https://docs.railway.com/networking/public-networking/specs-and-limits#technical-specifications.

SQLite schema migrations run before serving; unknown newer schema versions fail closed. WAL, full synchronous writes, foreign keys and secure deletion are enabled. Files use the provided path and standard SQLite siblings (`-wal`, `-shm`, and possibly `-journal`); known file symlinks are rejected. The root owns volume checks, ownership and dropping process privileges. DB records are purged on startup and hourly after the configured retention period (365 days by default). Delete and retention purge checkpoint the WAL after removing records. Any separately configured volume backups have their own retention policy and are outside this live-record service.

Only an authenticated owner can list, change status, delete or export. CSV fields are quoted, embedded quotes escaped and spreadsheet formula prefixes neutralised. The educational anonymous planner remains a separate browser-local store; it is not copied into this database.
